# Release Notes — Connected Steps v3.0.0

**Released:** 2026-07-28  
**Type:** Major release

---

## What's New in v3.0

Connected Steps v3.0 ships the Integration Platform — a complete developer-facing layer that lets external systems read from and respond to your Connected Steps account in real time.

---

## Integration Platform

### Public REST API (v1)

Your event data is now available via a versioned, authenticated REST API. Build registrations dashboards, sync participant data to your CRM, pull finance summaries into your accounting tool — anything your pipeline needs.

Nine endpoints covering events, registrations, participants, memberships, merchandise, and finance:
- `GET /api/v1/events` and `GET /api/v1/events/:id`
- `GET/POST /api/v1/registrations` and `GET /api/v1/registrations/:id`
- `GET /api/v1/participants`
- `GET /api/v1/memberships`
- `GET /api/v1/merchandise/products`
- `GET /api/v1/finance/summary`

All responses follow a consistent envelope: `{ data, meta }` for lists, `{ data }` for singles, `{ error: { code, message } }` for errors. Pagination is standard: `?page=&per_page=` (max 100 per page).

### API Keys

Org admins can create, rotate, and revoke API keys from the Developer Portal. Each key carries specific scopes — you decide exactly what each key can access:

- `events:read`, `events:write`
- `registrations:read`, `registrations:write`
- `participants:read`, `participants:write`
- `memberships:read`
- `merchandise:read`, `merchandise:write`
- `finance:read`
- `communications:read`, `communications:write`
- `webhooks:read`, `webhooks:write`
- `import:write`

Keys use the format `cs_live_<48 hex chars>`. The raw key is shown exactly once at creation — store it securely.

### Outbound Webhooks

Subscribe any HTTPS endpoint to receive real-time event notifications. Webhook delivery is durable: backed by the Postgres job queue, with up to 5 retry attempts on failure and full delivery logs in the portal.

Every delivery is signed with HMAC-SHA256 over `${timestamp}.${body}` and sent in the `X-CS-Signature` header — your receiver can verify authenticity and reject replays older than 5 minutes.

Available events: `registration.created/updated/cancelled`, `payment.succeeded/failed`, `participant.checked_in`, `certificate.generated`, `refund.completed`, `membership.renewed/expired`, `waitlist.promoted`, `merchandise.order_created/updated`.

### CSV Import

Bulk-load participants, registrations, volunteers, merchandise, sponsors, or coupons with a two-phase upload flow:

1. Upload your CSV — validation runs immediately and returns a full error report
2. If it looks good, commit — data is inserted in the background
3. Poll the job status until `done`

You see exactly which rows fail and why before any data is written.

### Event Automation Rules

Set up rules that automatically respond to platform events without writing code:

- **Triggers**: any of the 15 webhook event types
- **Conditions**: up to N conditions evaluated with AND logic (eq, neq, gt, lt, contains, not_contains)
- **Actions**: send email, send webhook to another endpoint, post in-app notification, generate certificate, add to waitlist

Example: when `payment.succeeded` and `amount_inr > 1000`, automatically generate a certificate and notify the volunteer team.

### Third-Party Connectors

Configure integrations with Google Calendar, HubSpot, QuickBooks, Mailchimp, Strava, and S3 directly from the Developer Portal. Each connector validates your credentials before saving and tests the live connection on demand.

### Developer Portal

All of the above is manageable from a new **Developer** section in the admin sidebar:

- **Developer Home** — platform overview, quick links
- **API Keys** — create, rotate, revoke, view usage per key
- **Webhooks** — manage subscriptions, view delivery logs, test live, replay failed deliveries
- **Import / Export** — upload CSV, view validation results, commit
- **Automations** — create and manage automation rules and view execution history
- **API Docs** — embedded endpoint reference
- **Monitoring** — API usage, webhook success rates, rate limit status

## Breaking Changes

None. v3.0 adds new surfaces without modifying existing APIs. Existing registrations, payments, QR codes, check-in, and certificate flows are unchanged.

## Upgrade Instructions

1. Apply the database migration:
   ```bash
   supabase db push
   ```
   This applies `20260728000010_integration_platform.sql` which adds 7 new tables, 1 view, and 1 RPC.

2. Create the `imports` Storage bucket (if not already present):
   - Supabase dashboard → Storage → New bucket → `imports` → Private

3. Deploy the new application build:
   ```bash
   vercel --prod
   ```

4. Verify: `GET /api/health` returns `ok: true`.

## Known Limitations

- Connector config values are stored as plaintext JSONB in `connector_configs`. App-layer encryption is not yet implemented. Avoid storing raw API secrets in connector configs until this is addressed.
- Automation rule actions execute synchronously in the request's `after()` block — very high-volume events may experience slight delays in automation execution.
- CSV import for `registrations` and `volunteers` requires `event_id` as a form field, not a CSV column.
